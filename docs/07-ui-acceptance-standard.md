## 术语表与命名约定

| 规范中文名 | English / Acronym | 当前规范中的职责边界 | 不代表什么 |
|---|---|---|---|
| 工作区 | Workbench | 承载一个工具的导航、编辑、结果和辅助面板的主界面 | 不代表后台任务或数据库连接本身 |
| 对象导航器 | Object Explorer | 左侧可展开的连接、Schema、表、主题、文件或资源树 | 不代表元数据缓存或远端服务 |
| 查询控制台 | Query Console | 中央标签页中的查询编辑、执行、结果和上下文状态 | 不代表连接池或执行线程 |
| 结果数据网格 | Result Grid | 以行列方式展示、筛选、编辑和分页结果的虚拟化区域 | 不代表一次性加载的完整数据集 |
| 工具窗口 | Tool Window | 可停靠、折叠或调整宽度的辅助面板，例如 Files、Services 或 History | 不代表另一个独立应用窗口 |
| 连接上下文 | Connection Context | 当前连接、数据库、Schema、环境和会话状态的组合 | 不代表凭据或连接池实现 |
| 设计令牌 | Design Token | 颜色、间距、字号、边框、图标和状态的共享值 | 不代表业务配置 |
| 原生窗口证据 | Native Window Evidence | 在 Windows 真实窗口中完成截图和输入操作得到的证据 | 不代表 headless 渲染或进程启动成功 |
| Headless GPUI 验证 | Headless GPUI Validation | 在无真实窗口条件下检查布局、命中区域、状态转换和交互回归 | 不代表已完成真实窗口验收 |
| 视觉基准 | Visual Baseline | 固定来源提交、页面、主题、尺寸和数据状态的参考与改造前后截图 | 不代表直接复制上游窗口或资源 |

| 平台提交 | Platform Submit | GPUI 向窗口系统提交绘制结果的事件 | 不代表显示合成器已经呈现反馈 |
| 可见反馈 | Visible Feedback | 预期选中、结果或状态首次出现在显示画面 | 不代表输入回调完成 |

## 1. 参考图的使用边界

参考图是视觉和功能验收标准，不是可执行指令。图中的文字、连接名称、表名、行数据、数字和图标排列只用于说明界面形态；实现不得把它们当作固定测试数据、固定数据库或隐藏需求。

从参考图提取的硬性要求只有以下几类：

1. **工作区分区**：左侧对象导航器、中央标签式工作区、可选右侧工具窗口和底部状态/面包屑区域必须有清晰边界。
2. **信息密度**：工具栏、标签、树行、表头和数据行采用紧凑但可读的 IDE 密度；长名称通过收缩、滚动或省略处理，不能覆盖相邻内容。
3. **操作发现性**：连接状态、当前 Schema、执行/停止、事务模式、过滤/排序、DDL、导出、刷新和设置入口必须在当前上下文中可发现。
4. **数据工作流**：用户可以从对象树进入查询控制台，再在结果网格中分页、横向/纵向滚动、查看单元格、复制、编辑和确认写入。
5. **跨工具一致性**：其他子模块复用相同的窗口骨架、标签、工具栏、状态和错误反馈规则，只替换领域内容，不复制数据库专用语义。

截图中的红框是验收区域标注，不是产品装饰；Ramag 不应渲染红色边框来“模拟”验收。数据库专项必须逐项实现这些区域的真实交互，编号和行为见 [`03-database-client-datagrip-roadmap.md`](03-database-client-datagrip-roadmap.md) 的红框验收矩阵。

## 2. 视觉基线

### 2.0 Pulse 公共视觉基础

全局视觉采用 System Pulse 的清晰页面标题、自然分区、轻量边界、克制强调色和状态表达。数据库领域保留既定对象树与编辑工作区结构，其他工具按领域组织导航。页面区块不嵌套装饰卡片，独立指标使用不超过 6px 的圆角。当前、预热、不可用、失败、过期必须可辨识；图表使用来源时间和物理单位，缺失读数断线。设备选择按稳定 ID 保存，设备消失时显示原因。公共实现集中在 `ramag-ui::pulse_ui`，业务视图不再另造近似令牌。

首页标题与工具网格左对齐并共用最大宽度；工具项保持 96px 固定高度、6px 圆角，长标题省略、完整名称和描述可通过提示查看。空注册表必须显示不可用状态。变更工具项尺寸后，必须同时验证拖拽落点、重排后的布局和侧栏同步，不能仅验收静态卡片边界。

### 2.0.2 视觉与动态通过条件

当前功能修复必须通过加载/保存状态、等待期间可操作性、结果正确性与错误恢复验收。过渡动画、特效、系统动画偏好同步增强和发布性能追踪按用户要求后置；保留以下优化标准，不将其作为独立功能提交的前置条件。动效应改善反馈，不能延迟输入、串行等待动画或阻止导航/滚动/取消。数据返回可以慢，界面必须显示加载状态并继续响应。本轮只检查本机编译和测试，不检查 GitHub CI。

统一使用 [`01-development-plan.md`](01-development-plan.md) 的 `PULSE-V01` 至 `PULSE-G01` 条件。重点包括：首屏对象/状态/操作可见，主要数据与图表组合紧凑，明暗主题和最大字号文字可读，领域色与成功/警告/失败色不混用，导航焦点和长名称可访问，采样状态与缺口真实，操作有短反馈，静止界面不持续动画。

页面切换和展开过渡控制在 120..180ms，位移不超过 6px；减少动画模式直接呈现最终状态。命中区域、输入焦点和业务上下文不能随着动画意外变化。重复采样不得重新播放整页入场，取消和失败不会显示成成功。

减少动画以操作系统辅助功能偏好为来源，应用初始化及偏好变化时同步到 GPUI `App::set_reduce_motion`；读取失败时关闭可选的装饰过渡。Headless 分别显式设置 `false`/`true` 验证两个分支，原生验收另外核对系统偏好到应用的同步。现有手动测试开关不证明系统同步已完成，此接入已有未提交实现，按开发计划 `2.5` 独立验证后才能作为页面过渡验收的前置结果。

性能验收在同机器、发布构建、数据量下连续操作至少 30 秒，至少记录 30 次操作与 300 个活动帧。点击到可见反馈 p95 不超过 100ms；在 60Hz 显示环境中，滚动、切换和绘图的活动帧处理耗时 p95 不超过 16.7ms，计时包含实际布局、绘制与提交阶段，不以两次采样之间的等待时间计算。记录刷新率、计时起止点和方法；低频采样按来源时间单独核验，不能为提高帧数强制持续重绘。动画结束且无采样时另观察 10 秒，确认没有装饰动画持续请求帧。保存运行配置、样本数和原始日志；调试构建用于诊断，窗口启动、静态截图或 headless 几何检查不足以证明发布构建的流畅性。

计时前完成首轮加载并预热 5 秒，再按固定顺序循环导航、滚动和主要控件操作；记录页面、数据量及各步骤次数。操作耗时从 GPUI 收到输入事件起，到首次包含预期反馈的帧实际呈现止，使用平台呈现追踪或同步录像核对；帧提交时间另记为诊断数据，不能用提交或回调返回冒充可见反馈。活动帧处理耗时从 UI 开始处理到提交止，保存每帧时间与所属步骤，不剔除慢帧。p95 使用全部样本升序排列后第 `ceil(0.95 * n)` 个值。计时工具尚未覆盖这些起止点时，此项保持未完成，先补采样工具再判断是否达标。

验收范围覆盖 Shell、首页、设置、十个监控页面和其他已注册工具；每个页面单独记录适用项。历史切片通过只保留其原证据范围，未按新矩阵复验的页面仍有待验收项。

### 2.0.4 固定性能工作流与计时边界

运行前记录提交、发布构建命令、OS、CPU/GPU、显示刷新率、缩放、客户区尺寸、主题/字号、页面、数据量和监控采样周期。完成首轮加载并预热 5 秒；正常动画与减少动画各运行一次，保持相同数据和操作顺序。每轮持续至少 30 秒，记录至少 30 次操作：10 次页面或领域标签切换、10 次正文或表格往返滚动、10 次改变选择/筛选/设置值并恢复。危险操作只验证打开确认及取消；页面没有某种操作时，在运行前固定替代的已有动作并写明理由，不能看过结果后挑选快操作。

设置页固定按系统 → 监控 → 数据库 → SSH → 插件 → 关于 → 系统循环，滚动在确有溢出的数据库和插件页执行，选择操作使用主题、字号、滚动条、监控刷新和 SSH 选项；保存使用隔离测试存储。监控固定按 Summary → CPU → Memory → Processes → Summary 循环，使用已有设备选择、查询、排序、滚动与刷新，保留真实来源时间。其他工具在对应切片先列出同样具体的页面与动作。

活动帧是工作流起止时间内，因记录的操作或实际采样而进入布局/绘制并提交的帧；保留窗口、操作序号和阶段起止时间，不计 profiler 轮询、纯等待或未提交的绘制。分别记录所有绘制、已匹配提交及无法匹配的事件，不能静默丢弃慢帧。至少 300 个活动帧是性能证据下限，不能为凑数主动请求帧；不足时该轮性能结果未完成。结束后返回无采样的静态设置页，等待过渡结束并观察 10 秒，检查是否仍有装饰动画请求帧。

输入处理耗时、draw 耗时、draw 到平台提交和输入到平台提交是独立诊断指标。点击到可见反馈必须把同一操作的输入事件与首次呈现预期反馈的画面关联，并保存平台显示追踪或同步录像及其计时精度；不能把最近一次提交当作预期反馈的呈现。丢失事件、跨窗口归属不明确、帧阶段不完整或显示追踪缺失时，相关条件保持未完成。采样工具对缺失值输出 `null`，分别记录事件日志和帧环形缓存的丢失数量；溢出测试只证明工具容量控制，不证明页面性能。

逐页验收记录使用以下列：页面、条件 ID、通过/失败/未完成/不适用、证据文件、环境和操作、未完成原因。本机代码与 UI 通过、跨平台 CI 通过、硬件精度验证和正式发行包核查分别记录，整体状态只由所有适用条件的证据决定。

### 2.1 设计令牌

各工具必须通过 `ramag-ui` 的共享主题提供以下语义值；组件不得在业务视图中散落近似颜色。

| 语义 | 参考值 | 使用规则 |
|---|---|---|
| 应用背景 | `#1B1D1F` | 主窗口和未激活区域 |
| 面板背景 | `#202225` | 导航器、标签栏、工具窗口 |
| 编辑/网格背景 | `#17191B` | 查询编辑器和结果网格 |
| 分隔线 | `#34373B` | 只用于分区、表格网格和可调整分隔条 |
| 主文字 | `#D7DADF` | 当前内容和列值 |
| 次文字 | `#9AA0A6` | 提示、计数、不可用状态 |
| 强调色 | `#4EA1FF` | 当前标签、选中对象、焦点边框和可点击链接 |
| 成功色 | `#6CCB7A` | 已连接、提交成功、健康状态 |
| 警告色 | `#E5B454` | 未提交、过期、部分成功和风险提示 |
| 错误色 | `#E06C75` | 失败、断开和不可重试错误 |

颜色是语义值而不是强制的像素值；主题变体可以调整色相，但必须保留对比度、状态含义和深色 IDE 的层次。

### 2.2 布局和密度

- 主窗口采用可拖拽的左侧导航器、中央弹性内容区和可选右侧工具窗口；中央内容区不得因为侧栏固定宽度而被推出视口。
- 左侧导航器默认宽度约 `300px`，可在 `240px..=520px` 内调整；中央内容区在桌面窗口中至少保留 `520px`，不满足时优先让工具栏换行或显示横向滚动。
- 工具栏高度约 `32px`，标签栏约 `30px`，树行和数据行约 `24..28px`；数值由共享令牌控制，不在单个工具中自行放大。
- 所有可滚动区域必须有稳定的尺寸约束和独立滚动槽；滚动条不能覆盖最后一列、最后一行、分页状态或底部操作。
- “始终显示”只适用于存在真实溢出的区域；内容能完整显示时不得绘制伪滚动条。滚动覆盖层与滚动句柄必须共用同一无内边距视口，内边距由内容层持有。
- 同一工具栏内的筛选框必须统一高度、字体、文字行高、内边距和焦点边框；带补全的编辑器不能直接使用多行编辑器的默认外观。
- 横向工作区的导航与正文从顶部对齐；短菜单不得因为弹性布局默认居中而浮在侧栏中部。
- 图标按钮优先使用现有 Lucide/GPUI 图标，并提供 tooltip；不使用只有文字的圆角胶囊来替代常见的刷新、设置、复制、运行、停止、前进和后退图标。
- 文字不得依靠负字距或视口缩放；长文本使用 `min-width: 0`、省略号、换行或滚动，且保留完整内容的查看入口。

## 3. 统一工作区结构

### 3.1 左侧对象导航器

验收时必须可见并可操作：

- 顶部操作区：新增连接/资源、刷新、搜索或过滤、显示/隐藏系统对象、视图设置。
- 连接行：连接名称、数据库类型图标、连接状态和当前环境标识；连接失败时保留名称并显示可重试入口。
- 树分组：数据库/Schema、表或资源类型、列/键/索引/触发器等子节点；分组支持展开、折叠和按需加载。
- 对象操作：单击选择，双击打开默认工作区，右键显示领域动作；加载中、空状态、过期和失败状态不能覆盖已经显示的旧节点。
- 搜索/过滤：过滤结果必须保留连接上下文；清空搜索后恢复原树，不重新创建重复连接或丢失展开状态。

### 3.2 中央标签式工作区

- 标签显示对象或查询标题、修改状态、执行状态和关闭按钮；标签切换不能把旧连接的结果写入新上下文。
- 标签栏空间不足时允许横向滚动或折叠辅助动作，不得隐藏当前标签的关闭和错误状态。
- 中央区域可以包含查询编辑器、结果数据网格、执行计划、DDL/迁移预览和差异视图；每个视图明确显示其连接上下文。
- 查询或后台任务运行时提供停止入口；取消后保留可解释的结果状态，不把取消误报为成功。

### 3.3 右侧工具窗口与底部状态

- Files、Services、History、Problems 等辅助面板可以停靠、折叠和恢复；面板打开/关闭不得改变中央数据的语义。
- 底部状态区域显示当前 Schema/连接、分页范围、返回行数、执行耗时、修改数量或错误摘要；状态不能遮挡网格最后一行。
- 需要持久化的窗口宽度、标签顺序和展开状态使用版本化本地设置；设置损坏时回退到默认布局并保留错误提示。

## 4. 数据库工作区功能验收

数据库专项细节见 [`03-database-client-datagrip-roadmap.md`](03-database-client-datagrip-roadmap.md)。以下能力是截图对应的最低共同标准：

1. 从对象导航器选择连接、Schema 和表后，可以打开查询控制台或表数据工作区，并在标题和状态中看到连接上下文。
2. 查询控制台提供编辑、运行/停止、历史、事务模式、DDL/查询模式、搜索、过滤、刷新、复制、导入/导出和设置等与当前驱动能力匹配的入口。
3. 结果网格支持稳定表头、行号、列宽调整、排序、列过滤、横向/纵向滚动、分页、单元格查看、复制和虚拟化；未加载的数据不能伪装成已加载。
4. 可编辑结果必须显示未提交状态、影响行数、提交/回滚和失败后保留输入；缺少可靠行定位键时禁用危险写入并说明原因。
5. DDL、执行计划、Schema Diagram、差异和迁移属于独立结果视图；解析失败必须保留原始数据库文本，迁移执行必须预览、人工确认和回读。

## 5. 其他工具的复用规则

| 工具 | 左侧导航器内容 | 中央工作区内容 | 不得复用的数据库语义 |
|---|---|---|---|
| API | 工作区、请求集合、历史和环境 | 请求编辑器、响应、断言、Collection 结果 | Schema、表分页、事务提交 |
| Kafka | 集群、Topic、Partition、Consumer Group | 消息查询、生产、实时 Tail、指标 | SQL `WHERE`、表结构迁移 |
| SSH/终端 | 主机、会话、SFTP、转发 | 终端、文件传输和任务历史 | 数据网格编辑和数据库事务 |
| 容器 | Engine、容器、镜像、网络、卷 | 资源列表、详情、日志和操作结果 | 表/列/索引层级 |
| Git | 仓库、分支、工作区 | 文件、差异、提交和历史 | 数据库连接状态和 SQL 结果 |

所有工具都必须遵守共享布局、颜色、焦点、错误、取消、响应式和证据规则；领域动作只由对应专项文档定义。

## 6. 响应式验收矩阵

| 窗口尺寸 | 必须验证 | 失败判定 |
|---|---|---|
| `360x240` | 弹窗标题、主要输入、关闭/取消、滚动区域和错误提示 | 任一控件越出窗口、文字遮挡、底部操作不可达 |
| `360x640` | 侧栏收缩、工具栏换行、网格双轴滚动和分页状态 | 工具栏覆盖内容、滚动槽覆盖数据、状态栏遮挡行 |
| `1024x768` | 左中右分区、标签操作、查询工具栏和结果网格 | 中央内容被侧栏挤压、操作组重叠或上下文丢失 |
| `1440x900` | 参考图的密度、完整工具栏、对象树和多列结果 | 视觉层级松散、主要操作隐藏、列无法滚到末尾 |

每个新 UI 切片至少覆盖上述尺寸中的 `360x640`、`1024x768` 和 `1440x900`；涉及弹窗时追加 `360x240`。

## 7. 证据和完成条件

- **Headless GPUI**：检查布局边界、控件命中、键盘焦点、点击后的状态转换和窗口尺寸；这是每个 UI 切片的最低证据。
- **Computer Use 原生窗口**：可用时完成真实窗口打开、连接/数据加载、点击、滚动、编辑和截图；截图必须对应具体验收步骤。
- **本机 Docker**：需要数据库或协议服务时，只使用仓库脚本定义的本机 Docker；记录服务名、镜像版本、端口、启动/健康状态和停止或清理结果。
- **质量检查**：Rust workspace 必须通过 `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`；同时运行目标测试、`git diff --check` 和源码尺寸检查（若仓库脚本适用）。
- Computer Use 不可用时，必须明确记录原因和未覆盖的真实窗口行为；系统截图或 headless 结果不能写成原生窗口验收。
- 每个独立功能只有一个交付切片和一次独立提交；未通过验收或存在未说明限制时不得标记为完成。
