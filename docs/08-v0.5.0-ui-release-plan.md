# v0.5.0 首页 UI 与发布计划

日期：2026-10-08。目标：统一第一方工具入口首页，修复数据源列表及剪贴板搜索状态，发布 v0.5.0。

## 范围与验收

- 管理型首页：DBClient、VCS、SSH、对象存储、Kafka、MQTT。共用标题层级、限宽页面、搜索及主要操作区、列表面板和状态表达。表头与行共用列边界，列表填充剩余视口并独立滚动，保留领域操作及稳定身份。
- 工作型首页：API、Container、剪贴板、JSON Path、协作。统一页面标题、工具栏密度和表面层级；编辑器、终端、监控图表及业务导航保留适用的布局。System Monitor 为现有视觉参考；首页和设置核对共享主题及导航回归。
- 功能修复：删除剪贴板搜索条目后立即更新结果和详情；撤销后恢复当前查询。过期搜索不能覆盖新状态，失败保留有效数据。
- UI 验证：明暗主题、16/18px 和 360/1024/1440 宽度；360 为原生最小宽度以下的防御检查。完整源码程序通过 Computer Use 逐个打开首页、检查搜索/滚动/空与失败状态及主要入口。原生、headless 与本机服务证据分别记录。
- 发布：workspace 产品版本与锁文件为 0.5.0。发布说明来自 v0.4.0 到最终发布提交的范围，使用双语章节和比较链接。annotated `v0.5.0` 标签触发官方三平台工作流；确认五个安装包、SHA256SUMS 和 update-manifest 共七个资产后才能宣布发布完成。

## 执行与验证

先完成 DBClient，再推广公共首页组件，修复剪贴板状态，运行受影响库测试、workspace 测试、fmt、严格 all-target Clippy、源码尺寸、LF 和差异检查，构建完整程序并进行真实窗口验收。布局和剪贴板逻辑不改外部服务协议；需要实际协议回读时仅使用本机 Docker，记录镜像、端口和清理结果。最终验证后按独立功能提交并推送 main，再提交版本和发布记录。

重复构建/CI 状态观察由只读监控子代理负责。CI 失败先修复失败原因，不能移动已发布标签或把待完成资产写成成功。回滚边界是共享首页组件、各入口渲染及对应测试、剪贴板状态和版本记录；不回滚用户配置或业务数据，不修改全局 Codex 配置。

## 执行记录

已完成首页统一和本地验证：DBClient、VCS、SSH、对象存储、Kafka、MQTT、API、Container、剪贴板、JSON Path 与协作入口已接入共享首页层级。DBClient 数据源行补齐名称、类型、地址、账号/数据库和操作列；剪贴板删除、撤销和过期搜索结果处理已覆盖测试。

2026-10-09 验证记录：`cargo fmt --all -- --check`、`git diff --check`、源文件尺寸检查和 workspace 严格 Clippy（`--workspace --all-targets -- -D warnings`）通过。完整 workspace 测试通过 117 个测试套件，共 2698 项通过、0 失败、19 项按仓库规则忽略。debug `ramag-bin` 构建通过。Computer Use 已在真实 Windows 窗口检查 DBClient 数据源列表、新建连接对话框、剪贴板首页、VCS 仓库首页、对象存储首页和新建账号对话框，入口可打开并取消；原生截图证据与 headless 测试分开记录。

发布预检确认 v0.5.0 尚不存在，GitHub 授权可用；当前工作流要求 annotated 标签且使用 Cargo 版本生成安装包。按用户要求不监测 GitHub CI；标签推送后只读取一次发布状态，未发布的资产不作为已完成证据。版本、变更日志和发布记录将在本地验证后提交并推送。
