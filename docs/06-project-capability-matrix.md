# 双项目能力归属矩阵

> 状态：现行边界
> 更新日期：2026-10-24
> 适用范围：`ramag-platform` 与 `it-tools-template`

两个项目完全独立。矩阵只描述功能所有权和应用场景，不描述运行时调用关系。两个项目不
共享进程、代码包、接口协议、凭据、存储或发布物。

## 1. 状态定义

| 状态 | 含义 |
|---|---|
| 保留/维护 | Ramag 保留现有实现，只做缺陷、性能、稳定性、安全、兼容性和 UI 维护 |
| 已移除 | Ramag 不再构建、注册或显示该功能；it-tools-template 可独立实现 |
| 独立实现 | it-tools-template 按自己的 Web/PWA/Electron 路线实现，不成为 Ramag 依赖 |
| 条件保留 | 仅表示维护现有原生采集，不表示新增产品入口 |

## 3. 边界规则

- Ramag 的“保留/维护”不要求 it-tools-template 复用 Ramag 的参数、错误、权限、取消、
  分页、进度或资源限制模型。
- it-tools-template 的 Web、PWA 和 Electron 实现不要求 Ramag 提供 Web 运行时，也不调用
  Ramag 进程或 crate。
- API 工作台内部的 JSON Path 变量和断言是 CAP-004 的组成部分，不恢复 CAP-001。
- 新增能力必须先得到用户明确说明；两个项目各自更新能力边界，Ramag 的任务只写入[主线开发计划](01-development-plan.md)。
- 当前任务只在[主线开发计划](01-development-plan.md)维护；旧迁移、协作和 JSON Path 设计通过 Git 历史查阅，不恢复为当前范围。

## 4. 验收和回滚

Ramag 的维护验收只证明 Ramag 自己的实现。it-tools-template 的 Web/Electron 验收单独记录。
移除两个工具时保留其他工具的用户配置、凭据、历史和数据库文件；恢复已移除功能必须得到
用户明确说明，并重新评估实现成本、平台范围和安全边界。
