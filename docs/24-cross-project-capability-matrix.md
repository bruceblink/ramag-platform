# 双项目能力归属矩阵

> 状态：P0 BOUNDARY-001
> 更新日期：2026-10-24
> 适用范围：ramag-platform 与 it-tools-template
> 目的：为每项现有能力指定产品所有者、平台范围和迁移条件

本矩阵是两个仓库的共同边界记录。修改能力所有者、平台范围或回滚条件时，必须同步更新
两个仓库中的同名文件。历史代码可以暂时存在，但不能继续产生两套新的产品功能。

## 1. 状态定义

| 状态 | 含义 |
|---|---|
| 迁移 | 产品入口和主要实现由 it-tools-template 承担；Ramag 进入兼容期后移除 |
| 保留 | 原生核心能力继续由 ramag-platform 独立提供，it-tools-template 不调用 |
| 条件保留 | 只有基准或安全检查证明 Electron 无法满足时，才保留 Ramag 实现 |
| 暂缓 | 当前不开发，不为两个仓库新增产品入口 |

## 3. 迁移检查条件

### 3.1 通用工具和工作台

- it-tools-template 有唯一工具入口、平台声明和数据处理声明。
- Electron 流程覆盖连接、加载、成功、失败、取消和关闭。
- Web 入口明确显示不支持的本机能力，不通过通用 Node 或 Shell 接口绕过限制。
- 用户配置、收藏、历史和敏感输入有读取、迁移或清理说明。

### 3.2 Ramag 原生核心

- Ramag 内部服务可以在无窗口环境启动，但只服务于 Ramag 自己的 GPUI 产品。
- Ramag 自己定义参数、错误、取消、分页、进度和结果上限。
- SSH 会话、PTY 输入、SFTP 传输、端口转发和关闭行为有独立状态记录。
- 日志不写入密码、令牌、完整连接字符串或完整业务数据。

### 3.3 条件保留能力

- 先提供 Electron 或 Node 实现的基准结果。
- 只有精度、资源上限、协议支持或安全边界不满足时，才保留 Rust 服务。
- 条件保留服务必须有独立能力 ID，不得恢复完整的第二套产品工作台。

## 4. 回滚边界

迁移按“新入口可用、旧入口停用、兼容期观察、删除旧实现”的顺序执行。
迁移失败时，只恢复对应的兼容入口和读取能力。不得删除用户连接、凭据、历史、收藏或本地草稿。
删除 Ramag 工具前，保留一个可读取旧配置的版本，或提供明确的迁移提示。

## 5. 下一步

1. 以 CAP-002 数据库和 CAP-009 普通系统监控作为 it-tools-template 的首批独立开发范围。
2. 在两个项目中分别记录功能完成情况，不把一个项目的运行结果作为另一个项目的测试证据。
3. it-tools-template 的替代功能稳定后，关闭 Ramag 对应导航和默认构建注册。
4. Ramag 继续独立收口 CAP-011，不建立跨项目调用。
